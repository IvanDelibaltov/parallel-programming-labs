# Умножение матриц с использованием CUDA

## Описание

Программа на C++/CUDA для перемножения квадратных матриц с использованием технологии CUDA (Compute Unified Device Architecture). Автоматическая верификация результатов через Python (NumPy).

## Структура проекта

| Файл | Назначение |
|------|------------|
| src/main.cu | Исходный код CUDA (умножение матриц + GPU kernel) |
| scripts/verify.py | Проверка результата через Python/NumPy |
| scripts/gen_matrix.py | Генерация тестовых матриц |
| scripts/benchmark_cuda.py | Серия экспериментов производительности |
| build.bat | Компиляция программы через nvcc |
| data/ | Папка для входных/выходных файлов |
| results/ | Папка для результатов бенчмарка |

## Входные данные (матрицы)

### Формат входных файлов

Матрицы хранятся в текстовых файлах:

- N — размер матрицы (первая строка)
- a_ij — элементы матрицы (разделены пробелами)

Создаются при помощи `scripts/gen_matrix.py` для выполнения тестов.

## Как проходят тесты и проверки

### Тест производительности (benchmark_cuda.py)

Для автоматизации проведения тестов используется модуль `benchmark_cuda.py`, который запускает `matrix_mult_cuda.exe` с разными параметрами.

В `benchmark_cuda.py` можно задать такие настройки, как:

- `BLOCK_CONFIGS` — массив, содержащий конфигурации сетки блоков (8×8, 16×16, 32×32)
- `REPEATS` — количество выполнений для усреднения
- `EXE_PATH` — путь до `matrix_mult_cuda.exe`
- `SIZES` — размеры матриц для тестирования

**Вывод:** Для матрицы 8000×8000 оптимальная конфигурация — 16×16, обеспечивающая производительность ~10.42 GFLOPS. Блок 8×8 показывает худшие результаты из-за недоиспользования вычислительных ресурсов GPU. Блок 32×32 упирается в ограничения регистров, что снижает эффективность.

## Анализ результатов

1. **Оптимальная конфигурация**: 16×16 показала наилучшие результаты для всех размеров матриц.

2. **Масштабирование**: Все конфигурации демонстрируют теоретически ожидаемое масштабирование O(N³).

3. **Малые матрицы (≤1600×1600)**: Различия между конфигурациями незначительны из-за доминирования накладных расходов на запуск kernel.

4. **Большие матрицы (≥4000×4000)**: Конфигурация блока становится критически важной. Блок 16×16 обеспечивает наилучшее время выполнения (~16.8 секунд для N=10000), в то время как блок 8×8 показывает худший результат (~52.1 секунды) — разница в производительности до 3.1×.

5. **Пиковая производительность**: ~10.42 GFLOPS на конфигурации 16×16 для матрицы 8000×8000.

6. **Ограничения**: Максимальный размер матрицы ограничен объёмом видеопамяти (4 GB VRAM) — для матрицы 10000×10000 требуется ~1.2 GB на каждую матрицу (тип float).

## Вывод

CUDA-реализация демонстрирует эффективное распараллеливание на GPU. Оптимальная конфигурация блоков — 16×16, обеспечивающая максимальную производительность ~10.42 GFLOPS. Для матриц размером менее 1600×1600 выбор конфигурации не критичен, но для больших матриц (≥4000×4000) разница становится существенной — до 3.1× между лучшей и худшей конфигурациями.

## Требования для запуска

- Видеокарта NVIDIA с поддержкой CUDA (Compute Capability 3.0+)
- CUDA Toolkit 10.0 или выше
- Компилятор: nvcc (MSVC)
- Python 3 с библиотеками: numpy, matplotlib
