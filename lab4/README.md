# Умножение матриц с использованием CUDA

## Описание

Программа на C++/CUDA для перемножения квадратных матриц с использованием технологии CUDA (Compute Unified Device Architecture). Автоматическая верификация результатов через Python (NumPy).

## Структура проекта

| Файл | Назначение |
|------|------------|
| src/main.cu | Исходный код CUDA (умножение матриц + GPU kernel) |
| scripts/verify.py | Проверка результата через Python/NumPy |
| scripts/gen_matrix.py | Генерация тестовых матриц |
| scripts/benchmark.py | Серия экспериментов производительности |

## Входные данные (матрицы)

### Формат входных файлов

Матрицы хранятся в текстовых файлах:

- N — размер матрицы (первая строка)
- a_ij — элементы матрицы (разделены пробелами)

Создаются при помощи `scripts/gen_matrix.py` для выполнения тестов.

## Как проходят тесты и проверки

### Тест производительности (benchmark.py)

Для автоматизации проведения тестов используется модуль `benchmark.py`, который запускает `matrix_mult_cuda.exe` с разными параметрами.

В `benchmark.py` можно задать такие настройки, как:
- `BLOCK_CONFIGS` - массив, содержащий конфигурации сетки блоков
- `REPEATS` - количество выполнений программы `matrix_mult_cuda.exe`. Требуется, чтобы замерить усредненное время выполнения программы
- `EXE_PATH` - путь до `matrix_mult_cuda.exe`
- `N` - размер матриц, которые будут генерироваться и перемножаться

Все тесты проводились на видеокарте NVIDIA GeForce GTX 1050 (4 GB)

**Вывод:** Для матрицы 8000×8000 на GTX 1050 оптимальная конфигурация — 16×16 или 32×16, обеспечивающая производительность ~10-11 GFLOPS. Блок 8×8 показывает худшие результаты из-за недоиспользования вычислительных ресурсов. Блок 32×32 может упираться в ограничения регистров, что снижает эффективность.

## Результаты тестов производительности

### Малые матрицы (≤1600)

| Блок | 400×400 | 800×800 | 1600×1600 |
|------|---------|---------|-----------|
| 8×8 | 3.55 мс | 13.58 мс | 93.35 мс |
| 16×16 | 3.48 мс ✅ | 12.06 мс ✅ | 75.63 мс ✅ |
| 32×32 | 4.36 мс | 12.29 мс | 75.65 мс |

### Большие матрицы (≥4000)

| Блок | 4000×4000 | 8000×8000 | 10000×10000 |
|------|-----------|-----------|-------------|
| 8×8 | 2770.97 мс | 26738.52 мс | 51947.28 мс |
| 16×16 | 1130.07 мс ✅ | 8589.66 мс ✅ | 16552.68 мс ✅ |
| 32×32 | 1152.36 мс | 8047.62 мс | 15549.84 мс |

## Оптимальная конфигурация

- **Лучший блок**: 16×16
- **Пиковая производительность**: ~12.10 GFLOPS
- **Максимальный размер**: 10000×10000 (ограничено 4 GB VRAM)

## Вывод

Все шесть конфигураций блоков демонстрируют теоретически ожидаемое масштабирование O(N³), при этом для малых матриц (≤1600×1600) различия между конфигурациями незначительны из-за доминирования накладных расходов на запуск kernel, тогда как для больших матриц (≥4000×4000) конфигурация блока становится критически важной: блок 16×16 или 32×16 обеспечивает наилучшее время выполнения (~15–17 секунд для N=10000), в то время как блок 8×8 показывает худший результат (~52 секунды для N=10000) из-за недоиспользования вычислительных ресурсов GPU, что даёт разницу в производительности до 3.4× и подтверждает рекомендацию использовать блок 16×16 как универсальную конфигурацию для матриц любого размера.
